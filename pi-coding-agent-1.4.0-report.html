技术深度解析

1. 图像分类器架构

Pi 1.4.0 扩展了 Codemode 的 models.classify() API，使其支持图像输入。这一变更涉及多个层面：

// 新增的图像分类能力
const result = await models.classify({
  model: 'jev-1.14',  // TypeSafe Jev 或 Cloudflare Clef
  input: [
    { type: 'text', text: '这张图片包含什么？' },
    { type: 'image', url: 'https://...' }
  ],
  classes: ['code', 'diagram', 'screenshot', 'other']
});

Provider 级别的兼容性配置现在也适用于分类器模型，通过 compat.imageInput 和 compat.sendImageOptInHeader 字段控制。

2. Codemode Worker 队列机制

之前版本中，当两个 Codemode worker 都忙碌时，新的脚本调用会立即失败。1.4.0 引入了等待队列：

💡 技术细节

脚本现在最多等待 60 秒等待空闲 worker。通过环境变量 PI_CODEMODE_MAX_WORKERS 可以提升 worker 上限（默认 2 个）。这一改进对并行 Codemode 调用和进程内子代理场景尤为重要。

3. 摘要生成优化

generateSummary() 和 generateSummaryWithUsage() 不再受 reserveTokens 参数限制。摘要请求现在使用模型的完整输出限制，解决了长推理导致摘要失败的问题。

// 之前：固定输出上限可能导致失败
// 现在：使用模型输出限制
const summary = await generateSummary({
  messages: conversationHistory,
  // reserveTokens 现在只控制何时开始压缩
  // 不再限制摘要输出长度
});

4. Rex 终端集成

Rex 终端支持包括三个关键特性：

  • OSC 8 超链接：终端内可点击的链接
  • 真彩色支持：24-bit RGB 颜色渲染
  • 内联图像：在终端中直接显示图像

关键 Bug 修复

会话与上下文管理

压缩后会话损坏修复

修复了响应在输出限制处被截断后会话损坏的问题：被截断的工具调用被省略但其工具结果被保留，导致后续请求被 provider 拒绝。

恢复会话扩展工具失效

修复了恢复会话和 /tree 导航导致扩展工具失效的问题。当分支在工具注册前记录工具时，扩展工具现在默认激活。

/compact 忽略指令修复

修复了 /compact 在压缩分割的 turn 开始时忽略指令的问题。

终端与 CLI

终端状态清理

修复了 Pi 异常退出时终端停留在鼠标追踪、焦点报告、Kitty 键盘和备用屏幕模式的问题。

Linux 剪贴板挂起

修复了 Linux 上在 Pi 中复制文本并用 Ctrl+Z 挂起后，shell 中粘贴挂起的问题。后台 wl-copy/xclip/xsel 进程随 Pi 一起被挂起。

并发对话框修复

修复了并发扩展 select/confirm/input/editor 对话框和 inline custom() 组件的问题：第二个对话框替换第一个，第一个 promise 永不 settle。

Provider 与模型

OpenAI Responses 缓存丢失

修复了 OpenAI Responses 模型在工具移除后每次延迟工具加载时丢失 prompt 缓存的问题。

自动重试增强

修复了自动重试未触发的多种情况：gateway 上游失败、Codex CLI 代理转发的流断开错误、Google Vertex OAuth token 刷新失败。

空白工具输出处理

修复了空白工具输出（如 bash 的 \r\n）导致 OpenAI Completions、OpenAI Responses 和 Google 请求返回 400 错误的问题。

Windows 兼容性

Shell 检测修复

修复了 Windows shell 检测拒绝可运行的 Microsoft Store shell 别名的问题。

PowerShell 路径查找

修复了 Windows 未安装在 C:\Windows 时，PowerShell 和 legacy WSL bash.exe 启动器找不到的问题。

UTF-8 BOM 处理

修复了 pi update 在 managed-install.json 以 UTF-8 BOM 开头时失败的问题（Windows PowerShell 5.1 会添加 BOM）。

破坏性变更

⚠️ 升级注意事项

Provider Attribution Headers：扩展的 before_provider_headers handlers 不再看到 OpenRouter、NVIDIA NIM 和 OpenCode 的 attribution headers。这些 headers 现在来自 pi-ai 的客户端身份。返回 null 仍可移除 header。

⚠️ API 变更

Summary API：generateSummary() 和 generateSummaryWithUsage() 现在忽略 reserveTokens 参数。摘要请求使用模型的输出限制。

升级指南

从 1.3.x 升级

  1. 备份配置和会话数据
  2. 运行 npm install -g @earendil-works/pi-coding-agent@1.4.0
  3. 检查扩展是否使用了 before_provider_headers，如有需要调整
  4. 如使用自定义摘要逻辑，注意 reserveTokens 行为变更
