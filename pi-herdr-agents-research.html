01 — 核心结论

一个「小众但工程纪律罕见」的异步子代理实现

八条判断，覆盖定位、机制、质量、血统与风险。

  1. 定位：平台锁定换机制完整必须在 Herdr 内以 HERDR_ENV=1 启动 Pi，其他终端复用器一律不支持。代价是可移植性，换来的是真实 pane、真实进程、workspace 级编排能力。
  2. 异步语义是硬契约subagent 立即返回，子代理完成后由 harness 自动以 steer 消息唤醒父代理；工具描述中反复禁止轮询、sleep、tail 日志——「fire-and-forget」写进了提示词与文档。
  3. 完成检测是三层的子会话 sidecar 文件为主证据、终端哨兵为兜底、JSONL 提取最终结果；结果超过 16,000 字符时保留头尾与会话路径后截断，完整版留在子会话里。
  4. 监督换了传输方式默认「文件唤醒 + 4.8 秒共享对账」，文件系统不可用时退回 1 秒轮询；作者基准显示 10 个子代理时 CLI 调用开销下降 84.5%。
  5. worktree 是显式契约，不是默认行为每次调用按需开启，base 先解析为精确 SHA，创建前写 ownership manifest，完成后报告 Git 事实；扩展绝不自动 push、PR、merge 或清理。
  6. 持久专家 = 会话代际，不是常驻进程策略（工具白名单、模型、thinking、worktree 租约）在一个代际内不可变；单任务串行、忙时拒绝、崩溃不复活，v1 明确不做自动恢复。
  7. 评审方法论比功能更值得看对抗式评审要求不同模型家族交叉验证、证据状态分级（reproduced / trace-backed / unverified）、覆盖率缺口显式传播为 INCOMPLETE，拒绝投票与置信分数。
  8. 风险集中在「年轻 + 单人 + 快变」6 周内 128 次提交、两次破坏性重构（Pi-only、删除 workflow 子系统）；127/128 提交来自同一作者，且真实 Herdr 集成测试不进 CI。

03 — 接口与角色

6 个主会话工具 + 6 个命令 + 2 个子端工具

接口面克制：主会话只暴露必要的启动、发送、停止、中断与恢复；角色通过 frontmatter 与可安装 role pack 扩展。

工具作用
subagent启动子代理，立即返回；支持 agent / model / thinking / fork / persistent / interactive / cwd / worktree / tools / skills
subagent_interrupt只中断当前 turn，保留子会话
subagent_send给空闲的持久专家派发下一个任务（忙时记录 rejected-busy，无队列）
subagent_stop优雅停止持久专家，等当前任务终态与进程退出确认

subagent_done 子端交互式子代理标记完成并退出；自主代理自动退出

04 — 运行机制

启动是一笔事务，完成是一份证据，交付是一条消息

从 pane 分配到结果回灌，每一步都有明确的证据来源与降级路径；不抢焦点、不重排用户标签页、不依赖轮询。

  1. 定位 checkout。按 Herdr 规范化路径匹配目标 workspace，包含子目录；非 Git 目录退回调用方 workspace。
  2. 分配 pane。普通子代理进扩展自有的 Agents 标签页，默认每页 4 个 pane，溢出开新页；worktree 才创建新 workspace。全程不抢键盘焦点。
  3. 投递启动脚本。以显式 pane ID 运行 shell 脚本，注入 PI_SUBAGENT_*、PI_DENY_TOOLS 等环境变量后拉起真实 pi --session … --model … 进程。
  4. 监督与投影。Herdr pane 状态为粗粒度权威，子代理活动快照补充工具级细节，投影为 8 种生命周期标签。
  5. 完成与投递。sidecar 为主、终端哨兵兜底；从子会话 JSONL 提取终稿，截断到 16,000 字符后作为单条 subagent_result 消息 steer 回父会话。

生命周期标签

startingactiveblocked waitinginterruptedstalled runningfinalizing

active 计入 header 的 active 计数；其余计入 open，全为 open 时 widget 边框转为琥珀色提示。stalled 由固定看门狗判定（pane 检查持续失败或 pane 消失且无完成 sidecar），进入与恢复都会向父代理发 steer；交互式子代理默认静默，避免用户在 pane 里工作被「还在等」的提示打扰。另有可选 no-progress 建议（默认 15 分钟，仅告警、绝不干预）。

换传输方式之后，监督开销降到七分之一

1 档 = 0.5 次 CLI 调用/秒（档数四舍五入，行尾为真实值）· 10 个子代理 · 20 秒窗口 · 3 轮轮换 · Linux · 2026-09-06
TICK ROWS · MONO-BASIC · FILE WAKE + BATCH VS 1S POLLING

同一次基准中，「证据 → 解析」平均延迟为 3.2 ms（唤醒方案）对 449.0 ms（强制轮询），最大对账探针间隔 4.82 s。基准只测监督进程与隔离 Herdr 进程树的 CPU tick，不包含父模型延迟。

完成投递的排障约定：若子代理结束但父会话没有拿到结果，先查父会话是否落盘了结果消息—— jq -c 'select(.type=="custom_message" and .customType=="subagent_result")' "$PI_SESSION_FILE" | tail -1。 有记录 = 启动与提取正常，应排查父会话唤醒与投递；无记录才回头查子进程。活跃 watcher 可跨 /reload、/new、/resume、/fork 存活，但整进程退出仍会中断交付。

Worktree 契约（十条不变式）

  1. 按调用显式开启。worktree:{branch, base?} 只作用于当前 spawn，不写进角色 frontmatter。
  2. base 先精确化。解析为 commit SHA，缺省取源 checkout 的已提交 HEAD；父仓未提交改动不会复制。
  3. 先写 manifest。落在 artifacts/<父会话id>/worktree-runs/<run-id>.json，状态机 provisioning → provisioned → running → ready_for_review / needs_help / failed。
  4. 创建不抢焦点。启动命令显式指向返回的 root pane。
  5. 完成后保留 workspace。成功、失败、求助三种结局都保留，父代理审阅后才由人显式 herdr worktree remove --workspace <id>。
  6. 只报告 Git 事实。path、branch、base/head SHA、commits ahead、改动与未跟踪文件、clean/dirty/conflicted；检查失败报 unknown，绝不猜测为干净。
  7. 绝不自动发布。扩展不 push、不建 PR、不 merge、不 cherry-pick、不切换父 checkout。
  8. 不接管他人资源。ownership 以返回的 ID 追踪，标签只作显示；用户自建 pane 永不被自动回收。
  9. 恢复受限。worktree 子会话拒绝 subagent_resume；整机重启后 v1 不会自动重新接管 watcher。
  10. 读权限不是沙箱。worktree 隔离的是 checkout，不是进程或权限。

持久专家与模型路由

会话代际
1 代际

逻辑 ID 不变，但策略在一个代际内冻结；任务结果写入仅追加的 delivery ledger；停止需进程退出确认，未确认则 fail closed。

并发上限
3 个专家

默认 persistent.maxAgents=3，到顶直接拒绝、不驱逐既有专家；与 pane 上限（每页 4 个）相互独立。

模型解析链
5 级

工具参数 → 角色 frontmatter → 每角色配置 → 全局默认 → 父模型；支持逗号分隔 fallback 列表，但 worktree 场景禁用（失败会保留分支，重试无法安全复用）。

07 — 优势与风险

值得借鉴的四个决定，与必须接受的五个代价

决定一 · 把「不许轮询」写进工具描述

用提示词约束模型行为，而不是指望模型自觉；配合单条结果消息，避免空 turn 与上下文污染。

决定二 · 完成检测分层

sidecar → 哨兵 → JSONL 三级证据，且明确「pane 关闭」不等于完成，给原子写入留 500 ms 宽限。

决定三 · worktree 只做隔离，不做发布

把 push / PR / merge / 清理全部留给父代理与用户，工具边界与责任边界一致。

决定四 · 评审要求跨模型家族

同家族不同模型只是「质量升级」，不算独立评审；严重候选需跨家族验证，无验证者则标 INCOMPLETE。

高

平台强绑定

必须 HERDR_ENV=1 且在 Herdr 内启动 Pi，其他终端复用器完全不支持；Herdr 自身是 AGPL 的 Rust 项目，用户面相对窄。迁移成本落在「换运行时」而非改配置。

高

单人维护

128 次提交中 127 次来自同一作者，GitHub 贡献者共 2 人。项目质量很高，但 bus factor 为 1，长期维护与安全响应依赖作者个人投入。

中

1.x 仍在快速破坏

6 周内两次架构级反转（Pi-only、删 workflow 子系统）。对本仓内部是减法，对外部使用者是必须跟随的迁移。

中

v1 能力边界清晰但受限

不做整机重启恢复、不复活持久专家、worktree 会话禁止 resume、Windows 无文件唤醒（退回轮询）、无自动 push/PR/merge/清理。

中

自动化测试的边界

真实 Herdr 集成测试是人工发布门禁、不进 CI；单元层跑的是 fake provider。机制承诺的可信度依赖人工带环境跑一遍。

低

热度与元数据

23★ / 9 fork，规模仍是早期项目；GitHub 仓库未填简介，独立测试 CI 工作流缺失，发现性与外部验证都有限。

08 — 适配判断

谁应该用，谁应该绕开

适合
Herdr 用户

已经在 Pi + Herdr 工作流里、需要并行 scout / worker / reviewer、要 worktree 隔离写操作、认可「父负责集成、子只做有界任务」分工的工程用户。

谨慎
追稳定 API

需要冻结接口、跨平台一致（含 Windows）或云沙箱级隔离的团队，应等 1.x 稳定或改用 VM/容器方案。

不适合
非 Herdr 用户

不用 Herdr 就没有运行前提；想「顺带多 agent」而不愿读文档与配置模型 ID 的用户，会被前置条件劝退。

三步验证路径

  1. 安装与环境。herdr → pi → pi install npm:pi-herdr-agents → /reload，确认 /subagent list 能列出 7 个内置角色。
  2. 跑通异步语义。并行发起两个 scout，观察输入框上方的 Subagents widget 与完成后的自动结果投递；再打断一个子代理的 turn，确认会话保留。
  3. 验证隔离与停止。用 /worktree 或在 subagent 里给 worktree:{branch} 跑一个写任务，核对完成后返回的 SHA / 改动清单，再手动 herdr worktree remove 清理。
